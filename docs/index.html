Why it exists

dsh web binds loopback on purpose

It has no way to tell you apart from anyone else who can reach the port. Its own documentation is direct about it:

The fence is a reachability policy, not authentication; the Web carrier provides no authentication layer.

DeepSeek Harness — dsh-client-connection

dsh-fleet supplies the missing layer, and the multi-machine view along with it. It does not fork dsh: the node plugin is an ordinary Cordis plugin over a gateway dsh already designed to be transport-agnostic.

The machine dials you

Uplink is outbound WSS. Laptops on hotel Wi-Fi, boxes behind CGNAT, a desktop that never got a public name — they all reach up. Nothing inbound is opened.

A phone is a real client

HTTPS is required, because the dsh client needs a secure context. Terminate TLS at a proxy, sign in, pick a machine. Bookmark /_fleet/ for the way back.

Bytes, not business logic

The control plane never parses dsh's API. Frames stay opaque. A dsh upgrade does not wait on a dsh-fleet release.

Still the real UI

The browser loads that node's own dsh interface through the uplink — not a clone of it. New buttons appear when the machine has them.

How it fits together

A control plane that moves bytes and nothing else

Genuinely local

Each machine runs its own agent. Builds, tests, git and language servers execute there, on the real filesystem. The control plane forwards; it never executes on anyone's behalf.

The real UI

Your browser loads that machine's own dsh interface, served through the uplink — not a reimplementation of it. New dsh features appear without a dsh-fleet release.

Opaque by design

The control plane never parses dsh's data. It moves frames, correlates ids, and applies its own access policy. Because it does not understand the API, upgrades do not break it.

Getting started

Two machines, five minutes

1

Bring up the control plane

Docker is the supported deployment.

cp deploy/.env.example deploy/.env    # change both passwords
docker compose -f deploy/docker-compose.yml up -d
2

Mint a token

Sign in, then create a token for yourself under Your account. The console shows it once, beside everything a machine needs.

3

Let a machine dial out

On that machine, install the plugin, start dsh web, and paste the address, username and token at http://127.0.0.1:3080/_dshf-setup.

dsh plugin --profile web add <the node plugin>
dsh web

Without a fleet URL the plugin stays inert, so installing it never changes how dsh web already behaves on that machine.

Before you deploy it

What this is not, yet

Pre-alpha, and the gaps are the kind worth knowing before rather than after.

  • No TLS and no rate limiting. Put a terminating proxy in front before exposing it; the default bind keeps it on loopback until you do.
  • One browser drives one machine at a time. The dsh client addresses its API and assets absolutely, so a machine takes the whole origin while you are in it.
  • The wire protocol is versioned but not stable. Node and control plane should be upgraded together.
  • Privileged methods — credentials, settings, the host's own file dialogs — are refused by default and every decision is recorded.
